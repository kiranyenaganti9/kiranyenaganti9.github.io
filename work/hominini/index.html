A report said more than the evidence supported.

Engineering case study: repairing the verifier in the DataGovernAI research prototype.

DataGovernAI research prototype · 2026

The failure

The prototype produces reports about work it has done, and a verifier is supposed to check those reports against evidence. The verifier accepted appended claims such as "all tests passed" even when the workflow had never established them. A report with valid source references could still overstate what had actually been done.

This is exactly the failure the research is about: a claim that is permitted to appear, but not supported.

The repair

I fixed the verification path and added targeted negative tests for the specific kinds of unsupported additions that had been accepted. Those additions are now rejected. The conclusion is narrow by design: the verifier rejects the cases the tests cover. It does not follow that every false claim will be caught.

Related prototype work

01

Repository to private report

A single run processed the public psf/requests repository through four workflow steps and produced a private report in 3.469 seconds, with no model calls and no changes to the external repository. One observation, not a benchmark.

02

Traceable source inspection

Six Python files from a pinned commit were inspected, with content hashes checked and source references included in the report. The code was not executed.

03

Complete findings

A formatting limit that silently dropped later findings was reproduced and fixed. A six-file regression test now checks that each fixture's source-linked finding survives report generation.

04

Artifact visibility

In an isolated application-level test, the submitting user could see the artifact and an unrelated user could not. Deployed multi-user security has not been established.

05

Diagnostic repair

An earlier fix explained a recorded execution limit without restarting work. A 56-test suite covers the gateway and diagnosis helper, separately from the verifier repair.

Research direction

A working paper, Runtime Accountability for Persistent LLM Multi-Agent Systems, proposes requirements for human authority, evidence, recovery and independent verification. It is distinct from the runtime-governance manuscript and does not yet have a public reading link.

Evidence status. Results are from the developer's local runs. A pinned, independently runnable reproduction package is not yet published, and the results have not been independently validated. Nothing here establishes production readiness, deployed multi-user security, or fully autonomous engineering.
